# 系統流程圖文件 (FLOWCHART.md) - 自動打工排班系統

本文件詳述了自動打工排班系統中的核心操作流程，涵蓋身分驗證、請假管理及自動排班的核心邏輯。

---

## 1. 使用者身分驗證與登入流程
確保只有經過授權的使用者才能存取系統，並根據權限（店長/員工）進行導向。

```mermaid
flowchart TD
    Start([開始]) --> Login[使用者進入登入頁面]
    Login --> Input[輸入帳號密碼/第三方登入]
    Input --> Auth{驗證身分}
    Auth -- 失敗 --> Error[顯示錯誤訊息] --> Login
    Auth -- 成功 --> LogAction[記錄操作紀錄]
    LogAction --> RoleCheck{判斷角色權限}
    
    RoleCheck -- 店長 Admin --> DashboardA[進入店長儀表板: 顯示人力熱圖、排班按鈕]
    RoleCheck -- 員工 Staff --> DashboardS[進入員工儀表板: 顯示個人班表、請假按鈕]
```

---

## 2. 員工請假與班表動態調整流程
描述員工提交請假申請後，系統如何與現有班表整合並通知管理者。

```mermaid
flowchart TD
    S1([員工發起請假]) --> S2[選擇請假時段與理由]
    S2 --> S3{該時段是否已有排班?}
    S3 -- 是 --> S4[系統標記受影響的班次]
    S3 -- 否 --> S5[直接提交申請]
    S4 --> S5
    S5 --> S6[店長收到審核通知]
    S6 --> S7{店長核准?}
    S7 -- 拒絕 --> S8[通知員工失敗] --> EndS([結束])
    S7 -- 核准 --> S9[更新 SQLite 資料庫]
    S9 --> S10{是否造成缺工?}
    S10 -- 是 --> S11[觸發缺工提醒通知店長]
    S10 -- 否 --> S12[更新顯示班表]
    S11 --> S12
    S12 --> S13[發送 Push 通知給員工] --> EndS
```

---

## 3. 管理者自動排班與通知流程
描述系統如何運用智慧演算生成班表，並處理衝突檢查與發布通知。

```mermaid
flowchart TD
    M1([店長發起自動排班]) --> M2[設定人力需求: 如各時段人數]
    M2 --> M3[讀取員工可用時段與請假紀錄]
    M3 --> M4[執行排班演算法: 職能、權重、公平性]
    M4 --> M5{是否存在排班衝突?}
    M5 -- 有衝突 --> M6[標記衝突點並建議手動微調] --> M7[店長確認/微調]
    M5 -- 無衝突 --> M7
    M7 --> M8[預覽班表與熱圖分析]
    M8 --> M9{確認發布?}
    M9 -- 暫存 --> M10[存為草稿] --> EndM([結束])
    M9 -- 發布 --> M11[更新資料庫正式班表]
    M11 --> M12[記錄操作紀錄: Audit Log]
    M12 --> M13[向所有受影響員工發送即時通知] --> EndM
```

---

## 4. 關鍵流程說明
1.  **衝突檢查 (Conflict Check)**：排班演算法在運算過程中，會同步檢查員工的請假狀態與已排定的班次，確保不會發生「一人分飾兩角」或在請假時段排班的情況。
2.  **即時通知 (Real-time Notification)**：為了滿足 PRD 中「1 秒內通知」的需求，當管理者點擊「發布」後，系統會透過非同步任務或推播服務即時發送通知。
3.  **視覺化回饋**：所有的排班異動都會即時同步至前端的熱圖與行事曆視圖。
